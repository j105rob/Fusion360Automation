# Fusion360Automation

Workspace for designing 3D-printable parts in Autodesk Fusion through the `fusion360` MCP server (Python API scripts).

**`RULES.md` is the distilled rulebook** - every design rule and guardrail in this project, written as rule / failure that produced it / assertable check, plus the current state of every part. It is a digest of this file and `research/design-for-fdm-printing.md`, not a separate source of truth: when a number changes, change it in the script first, then here, then there.

## Printer and material (defaults unless told otherwise)
- Voron 2.4, 350 mm bed, enclosed; 0.4 mm nozzle; 1.75 mm Polymaker ABS.
- Parts are designed to print with slicer supports **off**. Fix printability in the model, never by relying on the slicer.

## Working rules
- **Capture all research in markdown under `research/`**, one file per topic, with a date, the findings, and a Sources list of links. Update an existing file instead of duplicating a topic. Add new research files to the "Always load" list above when they're general design rules.
- Before calling any part done, run the checklist in `research/design-for-fdm-printing.md`: work out each body's print orientation, design overhangs out, add designed-in sprue fins only where unavoidable, chamfer the first layer, and check features are healthy and parts don't interfere.
- Keep designs parametric: user parameters for anything the user may tune (insert sizes, standoff heights, clearances).
- **Printer dimensional bias (measured 2026-10-23, Voron + Polymaker ABS): 0.07 mm per wall.** A 5.00 mm modelled hole prints **4.86**. Holes come out undersize and external features oversize by the same amount, so the two compound on any peg-in-hole fit. Compensate at BOTH ends: the baseplate carries `hole_clear` = 0.07 per side (modelled 5.14 -> prints a true 5.00, which also makes official accessories fit), and the clips carry `leg_clear` = 0.14 (modelled 4.76 -> prints ~4.90). **Re-measure a printed hole and reset both if the printer, nozzle or material changes** - do not treat these as constants.
- **A first-layer chamfer on a through-hole opens its underside, which is where a snap barb catches.** On the baseplate a 0.5 mm bed chamfer left the barb only 0.19 mm of catch; 0.3 mm gives 0.39. Keep the bed chamfer as small as elephant foot allows whenever something latches under the part.
- **Mouse ears only on SHARP bed corners.** A rounded footprint corner has no stress concentration to lift, so an ear there is redundant — it just adds a part to trim and a scar to clean. Round the corners instead; if they are already rounded, no ears.
- Default glue-joint clearance 0.15 mm per side; M2.5 heat-set inserts: 3.6 mm hole, 5 mm deep, 7 mm boss.

- **Apply the printer bias to EVERY cavity, not just the one you are thinking about (2026-10-24).** The nose pocket got the +0.14 correction and the clip cavity did not, so a 6.30 cavity on a 6.00 bar printed to 0.08/side and would not seat. When the bias rule comes up, grep the script for every clearance parameter and fix them all in one go.
- **A capture bead must sit ABOVE the part's top face, not merely clear of its corner radius.** The Zippo bead was derived as "lowest position tangent to the case's top corner", which put its centre 0.5 mm BELOW the top face: it met the case on the SIDE and the lighter sat loose with the arms touching its flanks. Derive it the other way - fix the bead centre just above the top face, then take the LARGEST radius that still clears the corner.
- **A cut that splits a body still reports 0 unhealthy.** Deepening the Zippo relief slot to -150 deg ran its inner arc through the cavity floor and cut each band into loose pieces; the timeline was clean and only the bounding box and volume showed it. Count `root.bRepBodies` before and after every cut, and check the geometry that constrains it (here: the slot's inner arc at `ccz + (cav_r+arm_t)*sin(theta)` must stay below the cavity floor).

- **Flexure rule (2026-10-24, REWRITTEN the same day - the first version of this rule was wrong and made the parts worse).** A snap arm fails where it is **ANCHORED**, not along its length. The prybar v1 arm that snapped was measured afterwards: its relief slot wrapped to -130 deg, leaving **0.66 mm** between the slot's root cap and the cavity floor, and the 0.5 mm bed chamfer cut that to **0.162 mm**. The Zippo band was worse at **0.016 mm**. They tore out at the root; they did not yield in bending.
  - **Measure the root web on the real faces.** `measure_root_web()` takes the relief slot's root cap and runs `measureMinimumDistance` to every other face, classified by direction: **ABOVE** the cap is the anchorage into the base (want >= 1.5 mm), **BELOW** is material down to the bed face (>= 1.2), **BESIDE** is usually the opposite slot, i.e. the column between them (>= 1.2). An analytic probe will not find this - the old one walked DOWN from the slot to the bed, reported 3.28 mm, and was true and irrelevant.
  - **Past -90 deg the root web stops being `arm_t` and starts collapsing.** Up to -90 the slot runs at a constant offset from the cavity corner so the web IS the arm thickness. Past -90 the cap tucks under the floor and the nearest cavity surface becomes the FLOOR PLANE: `web = -cav_r - (cav_r + arm_root + relief_w/2)*sin(th0) - relief_w/2`. **It does not depend on `base_t`** - floor and slot rise together - so raising the base does not fix it. Only a shallower wrap or a thicker root does.
  - **The 17.5 MPa "measured ceiling" was a misattribution and is retracted.** It blamed bending for a root that was a razor. The limit now comes from the material: these arms flex WITHIN the layer plane and carry >= 4 perimeters with no gap-fill bond line, so ABS in-plane yield ~40 MPa with a 2.5x factor -> **`SIG_LIMIT = 15.0` MPa**, evaluated AS PRINTED (`PRINT_BIAS = 0.07` added to the deflection, because cavities print under and the bead therefore reaches further in).
  - **TAPER the arm: thick at the root, thinner at the tip.** The bending moment is largest at the root and zero at the bead, so uniform thickness is wrong in both places. A thick root also pushes the relief slot outboard, which is exactly what thickens the root web - the taper fixes the stress distribution and the anchorage at once. Implemented by sloping the relief slot's INNER edge inboard over `arm_blend` while its outer edge stays vertical, so the rail keeps a constant thickness and the slot simply widens.
  - **Do not thin an arm to buy bead reach.** That was the previous rule's advice and it is backwards. `lip_over` (the reach) IS the deflection, so budget it against the stress limit; a stiff thick arm with a small reach gives far MORE grip than a thin arm with a big one (Zippo: 1.6 flat / 0.98 reach -> 1.3 kg, versus 2.8->2.0 taper / 0.60 reach -> **6.3 kg**).
  - **Flexure walls must still be an integer multiple of the extrusion width and >= 4 perimeters** (1.6 / 2.0 / 2.4 at a 0.4 nozzle); 1.2 mm is 2.86 extrusions and puts a gap-fill bond line down the middle of the flexure. Full write-up in `research/design-for-fdm-printing.md`.
- **Add the printer bias to every sliding clearance.** Cavities print ~0.14 under nominal (0.07/wall), so a 0.20 mm modelled clearance on a sliding fit is 0.06 real and binds. Start sliding fits at 0.5 mm modelled.
- **An arm between two voids prints THICKER, and that belongs in the flexure check (2026-10-26).** `flexure_check` biased the deflection for the printer (cavities come out ~0.07/wall under, so the lip reaches further in) but kept the MODELLED arm thickness. Wrong: a flexure arm sits between the cavity and the relief slot, both voids, both printing inward, so the arm comes out **2 x 0.07 = 0.14 mm thicker**. For an imposed deflection `sigma = 3*E*delta*t / (2*L^2)`, so stress scales with `t` and force with `t^3` - ignoring it under-reports stress ~5% and insertion force ~20%. Correcting it moved the prybar 14.6 -> **15.7 MPa (105%, over)**, the Zippo 14.3 -> 15.2 (102%, over, since cut to lip_over 0.55 -> 14.2) and the Skeletool 13.6 -> 14.2. **It is also the first thing to suspect when a part computes comfortably but is too stiff to press together by hand.** The same bias applies to any rib or wall bounded by two cut features, not just flexures.
- **Budget the INSERTION FORCE, not just the stress (2026-10-26).** Two parts were signed off at 95-105% of the stress limit, clear on interference, zero sticky zone - and came back as "there is no way this pry bar will fit" and "the Zippo still pops the lighter out", with **"stop worrying about tension, and make the parts fit."** What a person feels is `2 * k * (lip_over + PRINT_BIAS)`, and `k` had been maximised because every earlier fix spent its budget on retention. The prybar wanted **56 N** to press a 6 mm bar between two 12 mm arms. Cutting the reach took the three parts to 35 / 29 / 23 N with 6.4 / 5.3 / 4.3 kg of pull-out - still 20-180x the weight of what they hold - and dropped the stress to 69-77% for free, since the splay IS the deflection. **Print the push force beside the pull force**, quote retention as a multiple of the part's weight, and treat anything past ~20x as being paid for with the user's thumbs. Also: **`lip_clear` must be sized from how well the part was MEASURED** (0.40 on the caliper-checked Zippo, 0.60 on the spec-only Skeletool), never left at the printer bias - 0.10 became 0.05 as printed, so any error in the part's thickness put the lip back onto the part and held it proud. Full write-up in `research/design-for-fdm-printing.md`.
- **A face selected by RADIUS alone will eventually select the wrong face (2026-10-26).** `measure_root_web()` took "every cylinder within 0.05 of `relief_w/2`" as a relief-slot root cap. Cutting `lip_over` to 0.08 made the prybar's `bead_r` 0.58 against a `relief_w/2` of 0.60, so the capture bead was measured as a slot cap and the build cried `root web ABOVE cap: 0.300 mm ** THE ARM HANGS OFF THIS **` on a part whose web was 1.572. Fixed with a `below_z=base_t` filter - the caps are the only such cylinders under the cavity floor. Add a POSITION test to any check that picks geometry by one scalar.
- **A CYLINDER is the easy case: the part radius cancels out of the lip placement (2026-10-26).** Every Zippo failure traced back to a corner radius that was never measured, because the lip underside is the line `y + z = K` with `K = sqrt(2)*(R + clear) + w/2 + part_top - 2R`. Put a cylinder through it - `w = D`, `R = D/2`, `part_top = base_t + D` - and it collapses to `K = sqrt(2)*(D/2 + clear) + D/2 + base_t`, whose distance to the part's axis minus `D/2` is **exactly `clear`, for any D**. So a round holder needs no corner-radius estimate and no radius sweep; the only uncertain number left is the DIAMETER, and a part `dia_err` oversize eats `0.854 * dia_err` of `lip_clear`. **BUT THAT FORMULA IS ABOUT AN INFINITE PLANE, AND IT COST THE OLIGHT THREE PRINTS (corrected 2026-10-28) - see the rule below.** Size `lip_clear` from how well the diameter is known and sweep the diameter instead. **Two more things are free on a round part and are not on a flat-walled one:** (1) `cav_hw` cancels out of `lip_zt` and out of `K`, so cradle clearance changes the splay, the push force, the stress and the seated lip clearance by exactly nothing - only the band gets wider; (2) a cylinder nests at the bottom of a larger cylindrical cradle and self-centres there, so that clearance buys tolerance without buying rattle. Both holders run `cav_clear` 1.00 for that reason. **And make the cradle ROUNDER than the part, which is the reverse of the rounded-rectangle rule and for the same reason** - a cradle arc larger than the cylinder touches at one point at the bottom and cannot jam, while a smaller one catches it on two points up the sides and holds it proud.
- **A RETENTION FEATURE MUST BE AT LEAST ONE EXTRUSION WIDTH DEEP, AND TWO TO PRINT CRISPLY (2026-10-28).** The Olight band was loose five times. On the fifth, Rob measured the PRINTED band's opening at **15.34 against a bore of 15.36**: the throat WAS the bore, so **the capture lip had never printed, in any of the five prints**, and a 15.10 cap dropped straight through. `lip_over` was **0.35 - smaller than one extrusion width, and smaller than `lip_tipr` (0.40)**, so the two 45 deg faces never existed and the slicer deleted the whole feature. The 4-perimeter rule had been applied to the ARM and the one-nozzle-width rule to the lip's TIP RADIUS, and neither was ever applied to the lip's **REACH** - the dimension that does the work. **Assert `lip_over > lip_tipr` and `lip_over >= 2 * 0.4`.** Cause: the 2026-10-26 "FIT FIRST" pass cut every reach in the project to fix insertion force (prybar 0.08, Zippo 0.40, Skeletool 0.45, round 0.35) without checking any of them against the printer's resolution. **Why three of the four still work is the generalisable part:** Rob's verdict was *"the prybar is a super tight fit, the pill bottle is a super tight fit, the pen is a super tight fit... the flashlight has never been right"* - and the difference is **what sets the printed SIZE of the capture**. The prybar's tangent bead has radius `cav_hw - lip_tip_y` = **1.08 mm** and grows as the cavity opens, so it stays printable on a 0.08 reach; the pen has a 2.00 mm arc; the pill holder's lip does not print either but it grips by its **BORE**. A 45/45 lip's only dimension is the reach, so it is the one shape where a small reach means no feature at all. **Prefer a capture whose printed size comes from the CAVITY, not from the reach.**
- **A lip on a CYLINDER is held by friction, not by the spring (2026-10-28).** `pull = 2 * F * 1.8` was the pull-out model for every band here; 1.8 is the wedge factor of a 45 deg face and it is wrong on a cylinder, where the lip tip radius (0.40) is dwarfed by the part radius (7.55) so **the PART sets the escape ramp**. A cylinder near its equator is a nearly vertical wall = a nearly horizontal ramp: at `lip_over` 0.35 the ramp ran **18 deg at first touch down to 0 at release**, under arctan(mu) throughout, so friction did the holding and the resistance died away just as the part was escaping. Real peak **11 N, not 52** - the model was **4.8x optimistic** (3.6x on the Zippo), so every "kg of pull-out" on record in this file is 3-5x high. Two keepers: **pull-out on a smooth cylinder is only ~0.4x the press force whatever the clearances are**, so a light press and a firm hold cannot coexist there; and **the seated-to-free travel is pure geometry**, `sqrt(R^2 - y_tip^2)` = 2.5-3.5 mm on a 15 mm part, so a cylinder holder always moves before it bites. `escape_curve()` in `modgrid_round_holder.py` computes it and prints the ramp angle beside the force.
- **"Loose" is a DIRECTION, and nobody says which one (2026-10-28).** The Olight band was reported loose four times. Three fixes went in - `cav_clear` 1.00 -> 0.40, `lip_clear` 0.50 -> 0.30, then the `lip_z0` correction that cut free lift 1.52 -> 0.54 - **all three radial, while the complaint was AXIAL**: the light snapped in correctly and then slid along its own axis through the band. Hence "it still feels the same as the previous 2 iterations". **Ask at the FIRST report which way it is loose: does it rattle across, lift out, slide along, or fall out under load?** Four different defects, four different fixes, and the checks written for one are blind to the other three. Structural fact underneath it: these bands are designed so the arms are UNLOADED when seated (a splayed arm creeps in ABS), so **there is almost no friction along the axis** - every band-style holder needs an axial stop as an explicit feature, and only the Zippo had one.
- **Measure EVERY diameter of a multi-piece part, and then the step is free (2026-10-28).** The Olight had been modelled as one 15.10 cylinder for all 55 mm. That 15.10 was real but was the **keyring cap**; the body is **13.25**. Two consequences: (1) **the cradle band had never touched the light** - bored and sunk for 15.10, it sat 0.93 mm clear of a 13.25 body at every point, so one of the two bands was decorative, and the interference sweep reported CLEAR at every lift height, correctly, against a reference body that does not exist. **A reference model built from one measurement of a multi-piece part will confirm whatever you assumed.** (2) **The step is a ready-made axial stop**: bore the second band for the SMALLER section and put its BED FACE at the step, and the part's own shoulder lands on it - here 0.76-0.92 mm of engagement over 160 deg, measured on the solid. **Prefer a stop made of a face the part already has**: no clearance budget, no overhang, nothing to fillet. Three traps, all of which bit: **do not chamfer the stop face's inner edge** (0.50 off a 0.76 engagement - same rule as the barb catch; leave it sharp, elephant foot there ADDS material and the part drops in radially anyway); **a longer band still gets only ONE row of mount legs** (a second row a grid pitch along is right on the plate and wrong in the printer - the band stands on its bed face, so that row starts 16 mm UP the print as an island in mid-air); and **check how much of the grip band actually lands on the gripped section**, because the band is where the grid pitch puts it and the step is where the part puts it.
- **A clearance derived against an INFINITE face is not the clearance you built (2026-10-28).** The Olight band came back "still too loose" a third time after two defensible tightenings (`cav_clear` 1.00 -> 0.40, `lip_clear` 0.50 -> 0.30). The bore was never the problem - at 0.13/side printed it is as tight as the proven Zippo. The play was VERTICAL: **1.52 mm of free lift before the lip bit**, on a band 12 mm tall, while `lip_clear` read 0.30. **Cause: `lip_z0` placed the lip's underside LINE `lip_clear` off the cylinder, which is exact for an infinite 45 deg plane - but the real lip is `lip_proj` = 0.72 mm tall and sits well below where that line touches the part (the part's own 45 deg point, `z = part_z + 0.707*D/2`).** The part never reaches that face; its closest approach is to the lip's TIP RADIUS, which stood **0.67 mm** off a part the parameter claimed was 0.30 away. **Free lift goes as the SQUARE ROOT of the clearance**, so being 2.2x out on a tenth of a millimetre came out as 2.8x the rattle. Fixed with a closed form against the feature that exists - put the tip-radius centre at `R + clear + tipr` from the seated axis, `lip_zt = part_z + sqrt((D/2 + clear + tipr)^2 - lip_cy^2)` - valid because the arc's closest normal (~23 deg) lies inside the +/-45 deg the tip spans, which is worth checking rather than assuming. **Three rules: (1) when you simplify a feature to a line to derive a clearance, check the contact lands on the part of it you actually built - a derivation that never mentions the feature's EXTENT is the giveaway; (2) ASSERT the clearance against the model - `seat_check()` had been printing the real 0.70 in the same block as the 0.30 for three revisions and nothing compared them; (3) measure that assertion in the direction the parameter is defined in - the first version compared `lip_clear` to a HORIZONTAL gap and false-alarmed on the pill holder, whose contact sits at 30 deg.** And the process rule: **the same complaint twice means stop turning the knob and go measure what the part is actually touching.**
- **A snap must be checked for SELF-LOCKING, not just for clearance and stress (2026-10-25).** The Zippo band printed with a round capture bead passed every check - clear on interference, 92% of the stress limit, 2.0 mm root web - and the lighter still would not seat: it stuck ~2 mm proud with the arms splayed. Only the DOWNWARD component of the contact normal pulls the part home, and friction resists with mu*N, so the contact face must stay **steeper than arctan(mu) ~ 17 deg from horizontal** for the whole stroke. A round bead cannot: its normal runs centre to centre and rotates through horizontal at the crest, which on a 2.8 mm case corner is a 0.83 mm self-locking band. Fix is a **45/45 lip with a tip RADIUS of one nozzle width** (a flat land parks the part for its full width; a radius parks it for ~0.23 mm). Peak splay, and therefore stress and pull-out, are unchanged. Two more rules out of it: **a bead is only "above the top face" if its TIP reaches `w/2 - part_r`** (the Zippo's was 2.0 mm short, so all the capture was on the corner), and **place the lip off the SQUAREST plausible corner radius**, which biases the error toward "a bit loose" instead of "will not seat". `seat_check()` in both band scripts does this numerically. Full write-up in `research/design-for-fdm-printing.md`.

## Fusion API gotchas (learned the hard way)
- A script that raises an exception **rolls back everything it did**, even if the model built fine before the error. Keep reporting and verification code defensive, and re-check the timeline after any failure.
- Naming a sketch and its feature the same makes Fusion rename the feature to `Name (1)`. Look features up by a substring, or keep references from creation.
- Scripts run with `readOnly: true` can't change body visibility (`isLightBulbOn`) or anything else in the design.
- `BRepBody.pointContainment` returns an enum: 0 = inside, 1 = on the surface, 2 = outside.
- The root XZ construction plane's normal is +Y. Check `plane.geometry.normal` before choosing offset or extrude directions.
- For multi-body designs, set `participantBodies` on every JOIN/CUT extrude so features only touch the intended body.
- Check assembly interference with `TemporaryBRepManager` copies and an intersection boolean. Leave support bodies out of the check.
- Sketch geometry is created in **sketch space, not world space**. Convert with `sketch.modelToSketchSpace(point)` before adding curves. Passing world coords to a sketch on anything but the XY plane puts the geometry out of plane; the feature still builds but the profile silently breaks later with *"Curves tracked in old profile are not coplanar anymore"* (cost a whole rail-hole pattern on the rack frame).
- The **root component cannot be renamed** (`root component name cannot be changed`). Name the document instead.
- A **tapered cut that lands exactly tangent** to an existing hole wall fails with `EXTRUDE_CREATION_FAIL_ERROR`. For countersinks use `holeFeatures.createCountersinkInput(...)` instead of a tapered extrude, and let it cut the clearance hole too.
- Make cuts **direction-agnostic** where the far side meets no material: `setTwoSidesExtent(d, d)` avoids depending on which way a sketch profile's normal points.
- The `fusion360` MCP server is **built into Fusion** (`NsMCP10.dylib`), not an add-in; it will not appear under Scripts and Add-Ins. Config keys `MCPServerEnabled` / `MCPServerPort`, endpoint `http://127.0.0.1:27182/mcp`. If it accepts connections but closes them with no response, restart Fusion.
- When running scripts through the MCP server: entry point is `def run(_context)`, `print()` is the only output channel, **never call `ui.messageBox`** (it blocks the call), and do not catch exceptions — the traceback is the only debugging signal.
- **Numeric sketch geometry is not parametric.** Points passed to `addTwoPointRectangle` etc. are frozen numbers; only extrude distances and pattern counts follow expressions. For a sketch that must resize with a parameter, add driving dimensions (`sketch.sketchDimensions.addDistanceDimension(...)` then `dim.parameter.expression = 'plate_x'`) and anchor one corner with a coincident constraint to `sketch.originPoint`.
- **Chamfering a face only chamfers its OUTER loop**, not the inner loops. A face with 48 holes in it gets the perimeter chamfered and all 48 hole mouths left sharp. Verify by volume, not by eye.
- To chamfer a hole that gets patterned, **chamfer one cell then pattern the cut and the chamfer together**. Selecting the edges after the pattern stores one reference per edge and every one of them breaks ("Edge N missing") as soon as the pattern count shrinks.
- `Document.saveAs()` returns a **bool** (check it) and the cloud publish is **asynchronous**: the file will not appear in `folder.dataFiles` in the same script, so a save-landed check right after saving is a false alarm. Re-check in a later call.
- **Never `dataFile.deleteMe()` then `saveAs()` under the same name.** The delete is asynchronous and can land *after* the save, silently taking the new file with it. Worse, it can wedge the lineage server-side (`PIM data publish is not finished.` in the Fusion log under `.../2F62L7ANR7K4/logs/`), and a document in that state can no longer produce a temp file, so even STEP/STL export fails with `InternalValidationError` / `Failed to get temporary file`. To replace a design, open the existing document, `timeline.markerPosition = 0; deleteAllAfterMarker()`, rebuild, and `doc.save()` a new version.
- Meshes imported into these Fusion documents can be **10x oversize** (the MOD-GRID files are). Check a known dimension before trusting measurements off an imported mesh.
- **Sketch geometry is frozen numbers, so a parameter sweep must rebuild the body.** Re-expressing `case_r` and re-measuring gave an *identical* answer at every radius, because the reference body had already been drawn from numeric coordinates. For a sensitivity sweep, build a `TemporaryBRepManager` body per value (box + cylinder unions make a rounded rectangle) instead of editing the parameter.
- **A point added only to close a sketch profile must not sit on the functional LINE.** The reference bar's wedge was drawn from a start point lifted 1 mm clear of the top face "to be safe"; that tilted the line to 0.38/mm instead of 0.32/mm and moved the wedge start from x 55 to x 57.6, so the modelled bar came out up to 0.57 mm thicker than the analytic section the mating pocket was cut from. Close the profile on the far side, away from the edge that matters.
- **Verifying a cavity against an analytic model of the part is not verification.** The conformity probes read a clean +0.20 clearance the whole way while the real bodies overlapped by 15.6 mm3, because both the probe and the pocket used the same wrong section formula. Intersect the actual bodies with `TemporaryBRepManager`; the bounding box of the overlap points straight at the cause.
- **`addByThreePoints` may swap an arc's start and end** to keep its sweep direction, so on a mirrored side `arc.endSketchPoint` is NOT the point you passed last. Never close a loop by referencing an arc's SketchPoints - draw every connecting line from **explicit coordinates** and let the solver merge coincident points. Symptom: one side builds correctly and the mirror closes across itself (the prybar clip's left relief slot sealed itself at the arc's tangent point instead of running out the top, and the left cavity corner came out 1.236 mm instead of 1.571).
- **A chamfer bigger than the land it sits on does not error - it silently eats the part.** Chamfering a 0.50 mm land with 0.5 mm halved the prybar clip's volume and deleted its whole outer rail, and `timeline` still reported **0 unhealthy**. Guard it: skip any edge shorter than `2 * chamfer + margin`, and **check volume and bounding box after every chamfer**, not just health. The same cause shows up first as `ASM_BL_NON_MAN_EDVERT` ("non-manifold edge or vertex") when the overrun is severe enough to self-intersect.
- Do not chamfer an internal **relief slot** on the bed face. 0.5 mm off both sides of a 1.2 mm slot (and all the way round its rounded root cap) collapses it; elephant foot inside a relief slot is harmless anyway.
- When a build goes wrong, **log the body's bounding box and volume after every feature**. It localises the bad feature in one run; inspecting only the finished body cost several rounds of guessing here.
- - Rebuild pattern used so far: clear the timeline (`markerPosition = 0; deleteAllAfterMarker()`) and regenerate from one script. This **wipes manual edits**, so warn the user before doing it.

## Projects
- **MOD-GRID baseplate**: the script now names each document by grid size (`MOD-GRID Baseplate 12x8` etc.) so building a bigger plate does not overwrite a smaller one. `MOD-GRID Baseplate` (the original 12x4) and `MOD-GRID Baseplate 12x8` (99 x 67, 96 holes) both exist. The 12x8 carries **no mouse ears** - its corners are R3, so they are redundant; the older 12x4 document still has them. Change `grid_x`/`grid_y` defaults and re-run for a new size.
- **MOD-GRID baseplate (original entry)**: parametric baseplate for the MOD-GRID EDC system (TinyToolShop / 3dedc), `scripts/modgrid_baseplate.py`, saved to the `Mod Grid` folder as `MOD-GRID Baseplate` (the `MODGRID` folder holds the official downloaded files - leave those alone). Default 12 x 4 cells = 99 x 35 x 3 mm, matching the stock `MOD-GRID 4x12` exactly. `grid_x` / `grid_y` are live user parameters (outline is dimension-driven, holes are a 2-direction pattern); verified clean from 1x1 to 30x6.
